====================================================
 Diagnosing "AMRFinderPlus not found" on Windows
====================================================

pLIN tries to bridge to AMRFinderPlus running inside WSL automatically.
If it still says "not found," run the commands below in a normal
Windows Command Prompt or PowerShell window (NOT inside WSL/Ubuntu) to
find out exactly which step is failing. Copy the output of each step
and send it back.


STEP 1 -- is wsl.exe itself reachable from Windows?
------------------------------------------------------

    wsl.exe --status

Expected: prints your default WSL distribution's name and version.
If this fails ("'wsl' is not recognized" or similar), WSL isn't
installed/registered the way pLIN expects, and nothing past this point
will work -- see "IF STEP 1 FAILS" below.


STEP 2 -- can Windows run a command inside WSL at all?
-----------------------------------------------------------

    wsl.exe -e bash -lc "echo hello-from-wsl"

Expected output: hello-from-wsl
If this fails or times out, WSL is installed but not responding
normally to non-interactive commands from Windows.


STEP 3 -- the exact command pLIN runs to look for AMRFinderPlus
---------------------------------------------------------------------

    wsl.exe -e bash -lc "which amrfinder"

Expected: prints a path like /home/youruser/miniconda3/bin/amrfinder
(or similar). This is the actual command pLIN.exe runs internally.

  - If this prints nothing / says "amrfinder: command not found":
    AMRFinderPlus is on PATH inside an interactive WSL terminal, but
    NOT inside a login shell launched this way. This usually means
    your conda initialization (the block conda added to ~/.bashrc) is
    either missing, commented out, or guarded by a check that a
    non-interactive login shell doesn't satisfy. Try:

        wsl.exe -e bash -lc "cat ~/.bashrc | grep -A 3 'conda init'"

    and check whether that block exists and looks intact.

  - If STEP 3 prints the correct path here but pLIN still says "not
    found": something in the app's own error handling is swallowing a
    real problem silently -- send us this output along with STEP 1/2
    results and we'll dig into the app side.


IF STEP 1 FAILS (wsl.exe not found or not responding)
---------------------------------------------------------

Confirm WSL is actually installed and has a default distribution set:

    wsl.exe -l -v

If this lists no distributions, or none is marked as "Default," WSL
itself needs to be (re-)installed/configured -- that's a Windows/WSL
setup issue, not something pLIN can work around.


WHAT TO SEND BACK
--------------------

Please copy the exact output of Steps 1-3 (even if some fail) and send
it back -- this pinpoints exactly which link in the chain
(Windows -> wsl.exe -> WSL login shell -> conda PATH -> amrfinder) is
broken, so it can be fixed precisely rather than guessed at.
